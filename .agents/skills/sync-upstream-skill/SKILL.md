# 上流同期と意味パリティの監査

上流 `obra/superpowers` の更新を移植先の日本語スキルへ反映します。同期は「上流コミットが進んだか」の確認だけでは完了しません。上流が変わっていない場合も、移植先が記録済み上流の内容からドリフトしていないか監査します。

## いつ使用するか

- 上流に追随して最新化するとき。
- 「上流と内容に差がないか」「同期状態を確認して」など、移植内容のパリティを監査するとき。
- 上流更新がない場合も、移植時に意味が変わっていないか確認したいとき。

## 0. 比較基準を確定する

1. `docs/superpowers_ports.md` を読み、最新の対応表に記載された現在の移植対象、最後に記録された上流 SHA、意図的なファイル配置・プラットフォーム適応を確認します。このファイルを移植範囲と対応表の SSOT とします。時系列の過去記録は来歴であり、現在の対象一覧として復活させません。
2. `superpowers-original` の現在の HEAD と記録済み SHA を記録します。上流を更新する場合は `superpowers-original` で fetch し、依頼された更新先へ安全に切り替えます。未コミット変更やユーザーの作業を上書きしません。
3. **上流 SHA が変わっていない場合も続行します。** その場合は上流差分の抽出だけを省略し、現行上流 SHA のソースと移植先を全対象で照合します。「上流更新なし」を理由に監査を終了してはいけません。
4. 上流 SHA が進んでいる場合は、記録済み SHA から現行 SHA までの上流変更と、現行上流に対する移植先パリティの両方を別々に記録します。上流更新の有無と、移植先のドリフトの有無を混同しません。

## 1. 対象ファイルのインベントリ

- `docs/superpowers_ports.md` に記載された移植済みスキルと関連資産を対象にします。上流のアクティブなスキルディレクトリと、その `SKILL.md`、references、prompts、templates、examples、agents、scripts 等を再帰的に列挙し、移植先との相対パス一覧を照合します。
- `SKILL.md` だけでなく、動作や評価を変えるプロンプト、テンプレート、スクリプト、参照文書も照合します。
- 上流のみ、移植先のみ、相対パス変更、シンボリックリンクを一覧にし、既存の対応表に基づいて理由を確認します。理由のない欠落・追加はドリフトとして扱います。
- 移植履歴にない本プロジェクト固有スキルや設定は変更しません。`docs/superpowers_ports.md` に明記された開発ログの除外、別プラットフォーム用の代替例、ローカル専用参照は理由を保ったまま扱います。

## 2. 意味パリティの比較

各対象ファイルを対応する上流版と、次の観点で意味単位に比較します。

- 適用トリガー、適用範囲、使わない条件。
- 全ての分岐、選択肢、チェックリスト、承認ゲート、完了状態。
- 手順の順序、MUST / NEVER の強さ、数値、回数上限、タイムアウト、エスカレーション、停止条件。
- 状態名や機械可読トークン、引数、出力、証拠、報告形式。
- レビューの入力と判定基準、再試行と再レビュー、失敗・不明・環境要因の場合の経路。
- 補助スクリプトの入力、探索範囲、エラー処理、境界ケース、戻り値。
- 参照リンク、ファイルパス、前提条件。

日本語訳、図の記法変更、ツール名や配置のプラットフォーム適応は、それ自体を差分とはみなしません。ただし、分岐・挙動・強度・対象読者が変わる場合は意味ドリフトです。意図的適応は対応表に明記し、未記録の逸脱を「ハーネス適応」と推測して承認しません。

比較結果は次に分類します。
1. 上流で変更された内容（記録 SHA と現行 SHA の差）。
2. 移植先に欠落・追加・意味変更がある箇所（上流が不変でも検出する）。
3. 言語または実行環境だけの意図的適応。
4. 開発経緯など、移植時に意図的に除外した非実行時資料。

差分はファイルと節を特定して記録します。単なる文面比較だけで済ませず、文章が分割・統合・翻訳されている場合は、実際の判断経路を追って照合します。

## 3. 日本語移植への反映

- ユーザーが修正や同期を求めた場合、内容の差を上流の行動規則に合わせて修正します。監査のみを求められ、変更を求められていない場合は無断編集せず、差分と修正案を報告します。
- 英語の上流ファイルで日本語版を丸ごと上書きしてはいけません。日本語を維持し、欠落したロジックだけを意味に忠実にマージします。
- 文字列が機械可読、または他ファイルから参照される場合は、値を勝手に翻訳しません。プラットフォームのアクション名に置き換える場合は、実在する対象ツールへの対応と挙動を確認します。
- 新規スキルまたは大規模更新では `port-superpowers-skill` の分析・ドラフト手順を使います。スキル自体の執筆・変更では `writing-skills` の指示も確認し、必要な圧力シナリオを扱います。
- 判定が曖昧な変更は、ソース SHA、上流の原文箇所、移植先の箇所、推奨する日本語の修正を並べて人間に提示します。

## 4. 検証と記録

1. 変更した全ファイルを再度現行上流と照合し、参照切れ、抜けた分岐、強さや数値の変化がないか確認します。
2. `git diff --check` と差分・ファイル一覧を確認します。リポジトリに既存の検証手順があり、依頼と環境に合う場合のみ実行します。実行したものと未実行のものを区別して報告します。
3. `docs/superpowers_ports.md` に、比較した上流 SHA、対象範囲、修正点、除外、意図的なパス／プラットフォーム適応を記録します。上流 SHA が不変なら、ハッシュを更新したように書かず、同一 SHA でのパリティ修復・監査として記録します。
4. `requesting-code-review` の `code-reviewer.md` に従い、日本語の自然さと上流ロジックの保持を読み取り専用でレビューします。承認されるまで完了扱いにしません。
5. 対象プラットフォームで利用可能なら、そのネイティブなスキルローダーでロードを確認します（例: Antigravity CLI の `view_file` と `IsSkillFile: true`、Codex のネイティブロード）。ロード機構がこの環境にない場合は、frontmatter、相互参照、対象ファイルの存在を静的に確認し、物理ロードを検証していないと明記します。存在しない `activate_skill` 等を使ったと主張してはいけません。

## アンチパターン

- 上流 SHA が同じという理由だけでパリティ監査を終了する。
- `git diff` が空、または同一相対パスにあることだけで内容が同じだと結論づける。
- 日本語移植を英語で上書きする。
- 記録されていない独自改変をプラットフォーム適応として見逃す。
- 分岐、試行回数、承認ゲート、証拠要件、失敗経路の差を文体差として片付ける。
- 移植履歴にないローカル専用スキルを同期対象に加える。
- 読み込みを実行していないのに、動作検証済みと報告する。

## 完了の定義

- 上流 SHA の更新有無と移植先の意味パリティを別々に確認した。
- 対象の全ファイルと相対パス差をインベントリし、欠落・追加を説明した。
- 意味ドリフトを修復するか、監査のみの場合は根拠と修正案を提示した。
- `docs/superpowers_ports.md` に正確な SHA、変更、適応、除外を記録した。
- `code-reviewer` による日本語品質とロジック保持のレビューが承認された。
- 利用可能なスキルロード機構で確認したか、静的確認に留まったかを明示した。
