# セッション transcript のコンテキスト安全

1件の transcript 記録が1メガバイトを超えたり履歴全体を埋め込んだりすることがあります。1記録全体を出力すると診断作業中のセッションのコンテキストが溢れます。セッションファイルのすべての読み手（コントローラー、サブエージェントを問わず）は、すべてのファイルに毎回これらのルールに従います。

1. **読む前に測定します。**

   ```bash
   wc -lc "$F"
   awk '{ if (length($0) > 100000) print NR, length($0) }' "$F"   # 長行
   ```

2. **内容取得に `cat` や `grep` を使ってはなりません。** まず行番号と件数を取得し（`grep -n … | cut -d: -f1`、`jq -r '.type' | sort | uniq -c`）、次に特定行から小さなフィールドを取り出します（`sed -n Np | jq -c '{…}'` または `| cut -c1-500`）。目の前のソースについて発見時に確立したフィールド抽出コマンドを使用します。
3. **500文字超は絞ります。** 1記録に対するコマンド結果が500文字を超えたら、フィールドや範囲を絞ります。
4. **読み取り専用。** セッションファイルを変更・移動・削除してはなりません。
