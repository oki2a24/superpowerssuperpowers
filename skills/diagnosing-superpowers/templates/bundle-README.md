# Superpowers セッション診断バンドル

セッション: <session-id>
ハーネス: <名前> <バージョン> (<来歴ラベル>)    Superpowers: <バージョン> (<sha または "not a checkout">; <来歴ラベル>)
秘匿化レベル: skeleton | evidence | full
作成: <ISO タイムスタンプ>

ヘッダーのバージョン欄は、履歴証拠・未検証スナップショット・現在観測・不明のいずれかで修飾します。`environment.json` もすべての環境欄とその裏付け位置に同じ来歴区分を持ちます。

## これは何か

superpowers がインストールされ、うまくいかなかったコーディングエージェントセッションのスクラブ済み記録です。立ち会わなかったエージェントや人物が、superpowers が寄与したか、寄与したなら何を変えるべきかを判断できます。内部のレポートは `path:line` 証拠で何が起きたかを述べます。設計上、superpowers の診断も修正提案も含みません。それは読者の仕事です。

## ファイル

- `report.md` — 診断レポート（問題記述、判定、環境、セッション、タイムライン、finding、関与、網羅メモ）。
- `case.md` — アナリストが作業したケースファイル。
- `environment.json` — 環境セクションの機械可読複製。
- `timeline.md` — ターンごとのタイムライン。
- `findings/<dimension>.md` — 観点ごとの生アナリスト finding。
- `transcripts/<session-id>.md` — 各調査セッションの凝縮ターン描画（生 JSONL ではない）。ツール結果本文はレベル別:

  | レベル | ツール結果本文 |
  |---|---|
  | skeleton | 意図的に限定。`[tool result: <ツール>, <バイト数> bytes, exit <コード>]` に置換 |
  | evidence | 引用イベント分を保持。finding 裏付けに必要なコマンドと結果を含む |
  | full | すべて保持 |
- `scrub-log.md` — 使用プレースホルダとカテゴリ（原文値は決して含まない）。

## 読み方

`report.md` §1–2、次に §7（関与）と引用証拠行、次に `transcripts/` の対応ターンから読みます。`path:line` 参照は報告者マシン上の元ファイルを指します。凝縮 transcript 内では同じ行番号が `[L<n>]` マーカーとして保持されています。

## 秘匿化

プレースホルダは `<EMAIL-1>`、`<PERSON-2>`、`<SECRET-3>`、`<HOST-4>`、`<REPO-5>`、`<ORG-6>`、`<PROPRIETARY-7>` の形状です。ホームパスは `~/…` に書き換えられます。同一プレースホルダはバンドル内で常に同一原文値を指します。

## 作成者への指示

完成バンドルはこれらの指示を実際の結果に置き換えます。

スクラブ後、このバンドルのみを用いて出力したすべての重要な finding を検査します。引用を同梱 transcript/ソースマーカーに解決し、引用コマンド/結果や引用文を読み、主張を裏付けるか検証します。パスと行の存在だけでは不十分です。秘匿化レベルや必要な保留で裏付けが失われる場合、具体的な制限を記録します。

レポート、ケース、環境、finding、README、ローカル issue 草案を突き合わせます。ログ自身を除く最終ファイルに対してスクラブ ログ件数を更新します。古い出力記述を除去し、バンドル準備とアーカイブ配送を区別します。履歴アンカーから同梱証拠への対応を保持します。

プライバシー監査と証拠有用性を独立に記録します:
- プライバシー監査: CLEAN または未解決見逃し。
- 証拠裏付け: supported または limited。影響 finding と理由付き。

検査後に内容が変わったら、影響チェックを繰り返します。最終ログ、ファイル一覧、両結果を既存のアーカイブ承認に提示します。レビュー済みファイルをアーカイブし、配送アーカイブがそれらと一致するか検証します。アーカイブ配送は、承認後に内容を変えず、レビュー済みバンドルの外に記録します。スクラブは完全なプライバシー認証ではありません。
