# 計画の実行 (Executing Plans)

## 概要

計画をロードし、批判的にレビューし、すべてのタスクを実行し、完了時に報告します。

**開始時の宣言:** 「この計画を実装するために `executing-plans` スキルを使用します。」

**注記:** Superpowers はサブエージェントを利用できる環境（Claude Code、Codex CLI、Codex App、Copilot CLI、および Gemini CLI などが該当します。`../using-superpowers/references/` のプラットフォーム別ツールリファレンスを参照してください）でより高いパフォーマンスを発揮します。サブエージェントが利用可能な場合は、このスキルの代わりに `subagent-driven-development` を使用することを強く推奨します。

## プロセス (The Process)

### ステップ 1: 計画のロードとレビュー
1. 隔離されたワークスペースを確保します: `using-git-worktrees` スキルを使用して作成するか、既存のものを確認します。
2. 計画ファイルを読み込みます。
3. 批判的にレビューします — 計画に関する質問や懸念点を特定します。
4. 懸念がある場合: 開始する前にユーザーに問い合わせます。
5. 懸念がない場合: 計画項目のチェックボックス（`- [ ]`）を更新して進捗を追跡し、作業を進めます。

### ステップ 2: タスクの実行

各タスクについて:
1. 実行中 (In Progress) にマークします。
2. 計画に指定された各ステップを正確に実行します（計画は一口サイズのステップで構成されています）。
3. 指定された検証を実行します。
4. 完了 (Completed) にマークします。

### ステップ 3: 開発の完了

すべてのタスクが完了し、検証された後:
- 宣言: 「実装を完了するために `finishing-a-development-branch` スキルを使用します。」
- **必須のサブスキル:** `finishing-a-development-branch` スキルを使用します。
- そのスキルに従い、テストの検証、オプションの提示、選択したオプションの実行を行います。

## ヘルプが必要な場合の停止と質問

**以下の場合、直ちに実行を停止します:**
- ブロッカーに遭遇した場合（依存関係の不足、テストの失敗、指示の不明瞭など）
- 計画に重大なギャップがあり、開始できない場合
- 指示が理解できない場合
- 検証が繰り返し失敗する場合

**推測するのではなく、明確化のために質問します。**

## 以前のステップへの再訪問

**以下の場合、レビュー（ステップ1）に戻ります:**
- ユーザーがフィードバックに基づいて計画を更新した場合
- 根本的なアプローチの再検討が必要な場合

**ブロッカーを強行突破（force through）しないこと** - 停止して質問してください。

## 重要な注意点
- まず計画を批判的にレビューします。
- 計画のステップに正確に従います。
- 検証をスキップしないでください。
- 計画が指示するスキルは `activate_skill` を使用して参照します。
- ブロッカーに遭遇したら直ちに停止し、推測で進めないでください。
- **絶対厳守**: ユーザーの明示的な同意なしに、`main` または `master` ブランチで実装を直接開始してはなりません。
