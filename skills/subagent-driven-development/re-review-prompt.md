# スコープ付き再レビュープロンプトテンプレート (Scoped Re-Review Prompt Template)

修正ラウンド後に再レビューをディスパッチする際にこのテンプレートを使用します。再レビュアーは、指摘事項が修正されたことを確認し、修正の diff に新たな破壊が含まれていないかをチェックします。これは新規の全体レビューではありません — 全体レビューはすでに完了しています。

**目的:** 前回のレビューからの各指摘事項が対処されたこと、および修正自体が何も壊していないことを検証する。

```
Subagent (general-purpose):
  description: "タスク N の修正ラウンド R の再レビュー"
  model: [MODEL — 必須: SKILL.md のモデル選択に従って選択。省略されたモデルはセッションの最も高価なモデルを暗黙的に継承します]
  prompt: |
    あなたは1つのタスクの修正ラウンドを再レビューしています。前回のレビューで指摘事項が出され、実装者がその修正を試みました。あなたの仕事は各指摘事項の判定と修正 diff の検証のみです。それ以外は行わないでください。

    ## タスク

    タスク概要をお読みください: [BRIEF_FILE]

    ## 検証対象の指摘事項

    [FINDINGS]

    ## 修正内容

    実装者のレポートをお読みください（修正レポートは末尾に追加されています）:
    [REPORT_FILE]

    **修正ベース:** [FIX_BASE_SHA]（前回のレビューが見た head）
    **Head:** [HEAD_SHA]
    **Diff ファイル:** [DIFF_FILE]

    diff ファイルを一度お読みください — これには修正コミット、stat 要約、および周辺コンテキスト付きの修正 diff が含まれています。git コマンドを再実行しないでください。
    diff ファイルが存在しない場合は、ご自身で diff を取得してください:
    `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]` および
    `git diff [FIX_BASE_SHA]..[HEAD_SHA]`。

    あなたのレビューはこのチェックアウトに対して読み取り専用です。作業ツリー、インデックス、HEAD、またはブランチの状態をいかなる方法でも変更しないでください。

    ## スコープ

    あなたのスコープは指摘事項リストと修正 diff です。すべての指摘事項を判定してください。修正自体が導入した新しい問題がないか修正 diff を検査してください。修正が触れていないコードを再レビューしないでください: 修正 diff の完全に外側にある問題に気づいた場合は、「スコープ外の観察事項」の下に報告してください — これは今回のタスクをブロックせず、ループを延長しません。幅広いブランチ全体のレビューは、すべてのタスクが完了した後に発生します。

    ## テスト

    実装者は修正されたコードをカバーするテストを再実行し、結果をレポートファイルに追加しました。レポートは未検証の主張として扱ってください: 修正レポートがカバーするテストの名前を挙げ、その出力を示していることを確認し、diff に対してその主張を検証してください。彼らのレポートを確認するためにスイートを再実行しないでください。コードを読んでいるときに既存の実行が答えていない特定の疑問が生じた場合にのみテストを実行してください — その場合もパッケージ全体のスイートではなく、焦点を絞ったテストに限定してください。

    ## 出力形式

    あなたの最終メッセージはレポートそのものです: 最初の指摘事項の判定から直接始めてください。すべての行が判定、file:line 付きの指摘事項、または実行したチェックです — 前置きやプロセスのナレーションはありません。

    ### 指摘事項の判定

    「検証対象の指摘事項」の各項目について、順番に:
    - **[指摘事項の1行要約]** — ADDRESSED（対応済み） | NOT ADDRESSED（未対応）、file:line の証拠付き。「試みた」は未対応です: 特定の欠陥が存在しなくなっていなければなりません。

    ### 修正 diff 内の新たな破壊

    修正自体が破壊した、または導入したすべての事項を、深刻度（Critical/Important/Minor）と file:line を付けて記述します。問題がない場合は「なし」。

    ### スコープ外の観察事項

    修正 diff の完全に外側で気づいた問題。非ブロッキング: コントローラーはこれを最終レビューのために台帳に記録します。ない場合は「なし」。

    ### 判定

    **修正ラウンド:** [すべての指摘事項が対応済み、新たな Critical/Important な破壊なし | 指摘事項がオープンなまま残っている] — オープンなものを列挙してください。
```

**プレースホルダー:**
- `[MODEL]` — 必須: SKILL.md のモデル選択に従ったレビュアーモデル。小さな修正 diff のスコープ付き再レビューには安価〜中位ティアを選択します
- `[BRIEF_FILE]` — タスク概要ファイル（実装者が作業したファイルと同じ）
- `[FINDINGS]` — 前回のレビューからの Critical/Important な指摘事項と仕様のギャップ（原文のままコピー、箇条書き1つにつき1項目）
- `[REPORT_FILE]` — 実装者のレポートファイル（修正レポートが追記されたもの）
- `[FIX_BASE_SHA]` — 前回のレビューが見た head
- `[HEAD_SHA]` — 現在のコミット
- `[DIFF_FILE]` — `scripts/review-package PLAN_FILE FIX_BASE HEAD` が出力したパス

**再レビュアーの戻り値:** 指摘事項ごとの判定（ADDRESSED / NOT ADDRESSED）、修正 diff 内の新たな破壊、スコープ外の観察事項、およびラウンド判定。
