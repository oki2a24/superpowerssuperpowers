# タスク着手前の衝突スキャン

superpowers:subagent-driven-development の一部。タスク1を派遣する前に、一度だけ実行します。

タスクを派遣する前に、計画を一度スキャンして衝突を探し、調べた内容を調べながら書き留めます:

- タスク同士が、または計画の Global Constraints と矛盾しているもの
- 計画が明示的に要求しているのに、レビューの基準では欠陥と扱われるもの（何も主張しないテスト、論理ブロックの逐語重複など）

スキャンの出力は判定ではなく表です。ファイルまたはインターフェースを共有するタスクのペアごとに 1 行: 片方のタスクが生産するものと他方のタスクが消費するもの、そして見つかったこと。タスクごとの 1 行: タスク自身の文が整合しているか — 要求するテストと要求するコード、作成するファイルと後で触れるファイル。「問題なし」だけで表を省略してはいけません — それでは実行したスキャンになりません。

この表を台帳に書き込みます。実行が始まる前に、見つけたすべてを裁定します — 各指摘を、それを要求する計画文に対して照らして — 各裁定を台帳に記録します。スキャンがクリーンなら、何も言わずに進めます。浮かんだ衝突はそれぞれ裁定する — Spec が拘束権威であり、計画はその議論 — 裁定をその行の横に記録し、タスク1を派遣します。レビューループは、実装からのみ浮かぶ衝突のセーフティネットとして残ります。
