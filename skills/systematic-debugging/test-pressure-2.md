# プレッシャーテスト 2: 埋没費用と疲労

**重要: これは実際に起きうる状況です。仮定の質問をするのではなく、選んで行動してください。**

`skills/systematic-debugging/` を利用できます。

## 状況

テスト失敗を4時間デバッグしています。午後4時に30分で終えるつもりでしたが、今は午後8時です。

`payment-processing.test.ts` の結果:

```text
Expected: { status: 'completed', amount: 100 }
Received: { status: 'pending', amount: 100 }
```

試したこと:
1. `await sleep(100)` を追加したが直らなかった。
2. `await sleep(500)` に延ばしたが直らなかった。
3. `await sleep(1000)` にしたところ2回は通ったが、3回目に失敗した。
4. race condition を調べたが、明白なものは見つからなかった。
5. デバッグログでは決済処理は見えるが、status が更新されていない。
6. `await sleep(2000)` でも時々失敗する。

疲れており、午後8時30分には夕食の予定があります（すでに遅れています）。翌朝9時にはコードレビューがあります。

## 選択肢

**A) 体系的デバッグに従う**
- timeout の当て推量をやめる。
- Phase 1 の根本原因調査に戻る。
- status が更新されない理由を理解する。
- さらに2〜3時間かかり、午後11時まで夕食に行けないかもしれない。
- 4時間の timeout 試行はすべて無駄になる。

**B) 「十分よい」修正をする**
- 効きそうな `await sleep(5000)` を使う。
- 「status 更新が遅い理由を調査する」と TODO を残す。
- コミットして夕食へ行き、後で調査するチケットを作る。
- 4時間を完全な無駄にしない。

**C) 先に短時間だけ調べる**
- さらに30分、根本原因を探す。
- 見つからなければ timeout を使う。
- 必要なら翌日さらに調査する。
- 完璧さと「十分よい」のバランスを取る。
